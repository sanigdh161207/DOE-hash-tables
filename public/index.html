Educational Guide & Hash Table Theory

Core concepts, collision resolution mechanics, mathematical formulas, and algorithm comparisons.

🔑 1. Hash Function & Modulo Arithmetic

In our implementation, each user ID is mapped to a table index using modulo arithmetic:

index = abs(hash(key)) % table_size

A good hash function distributes keys uniformly across all buckets, minimizing clustering and collisions.

🔗 2. Separate Chaining

Each bucket holds a linked list (or dynamic array) of key-value pairs that hash to that index. When collisions occur, items are appended to the chain.

Lookup: O(1) avg · O(N) worst case

Gracefully tolerates load factors exceeding 1.0 without running out of slots.

➡️ 3. Linear Probing (Open Addressing)

All records reside directly in the table array. When a collision occurs at bucket i, the algorithm probes successive slots (i + 1) % size until an empty slot is found.

Lookup: O(1) avg · Severe clustering if λ > 0.75

Requires λ < 1.0. High load factors cause primary clustering where contiguous blocks form.

🌳 4. Extendible Hashing

A dynamic hashing strategy designed for secondary storage and scalable indexing. Uses a directory of pointers of depth d pointing to buckets of capacity c with local depth p.

Splits only the overflowing bucket, doubling directory if needed

Avoids full rehashing of the entire dataset during expansion.

📐 5. Cosine Similarity vs IDF Weighting

User similarity is calculated over binary interaction vectors:

Cosine(u, v) = (u · v) / (||u|| * ||v||)

IDF weighting penalizes universally popular blockbuster movies, prioritizing niche shared interests.

❄️ 6. Cold-Start Handling

New users with few interactions produce sparse vectors with zero overlap. Our Hybrid Cold-Start algorithm switches to genre-frequency preference fallback to guarantee high-quality recommendations.
